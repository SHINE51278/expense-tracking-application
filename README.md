Agile and Scrum simulation project for an Expense Tracking Application.
A# Expense Tracking Application
### Agile & Scrum Simulation — Case Study 16

## 1. Project Overview

The Expense Tracking Application is a personal finance management system designed to help users record income and expenses, categorize transactions, monitor their spending, and generate monthly financial reports.

This project demonstrates the application of **Agile methodology and the Scrum framework** through product backlog management, sprint planning, incremental delivery, sprint reviews, and retrospectives.

## 2. Problem Statement

Managing personal finances manually can be time-consuming and make it difficult to identify spending patterns. This application aims to provide a centralized platform for recording financial transactions and understanding income, expenses, and savings.

## 3. Project Objectives

- Provide secure user registration and login.
- Record and manage income and expenses.
- Organize transactions into categories.
- Display total income, expenses, and remaining balance.
- Generate monthly financial summaries and visual reports.
- Develop the system incrementally using Agile and Scrum practices.

## 4. Target Users

- College students
- Working professionals
- Individuals who want to manage their personal finances

## 5. Scrum Team Roles

| Role | Responsibility |
|---|---|
| Product Owner | Defines requirements and prioritizes the Product Backlog. |
| Scrum Master | Facilitates Scrum events and helps remove impediments. |
| Developers | Design, implement, test, and deliver the application. |

## 6. Product Backlog

| ID | User Story | Priority |
|---|---|---|
| PB1 | As a user, I want to register and log in securely so that my financial data is protected. | High |
| PB2 | As a user, I want to record income so that I can track my earnings. | High |
| PB3 | As a user, I want to record expenses so that I can monitor my spending. | High |
| PB4 | As a user, I want to categorize transactions so that I can understand my spending habits. | High |
| PB5 | As a user, I want to view my financial summary so that I can understand my balance. | High |

## 7. Sprint Plan

### Sprint 1 — Authentication and Transactions
**Goal:** Build the foundation for user access and transaction recording.

Planned tasks:
- Design the basic application interface.
- Implement registration and login.
- Add income and expense recording.
- Store transaction information.
- Test the core features.

**Expected Increment:** Users can access the application and record income and expenses.

### Sprint 2 — Categories and Dashboard
**Goal:** Enable users to organize transactions and monitor their finances.

Planned tasks:
- Implement transaction categories.
- Add transaction editing and deletion.
- Calculate total income and expenses.
- Display the remaining balance.
- Test dashboard calculations.

**Expected Increment:** Users can organize transactions and view their financial summary.

### Sprint 3 — Reports and Testing
**Goal:** Provide financial insights and prepare the application for demonstration.

Planned tasks:
- Generate monthly expense reports.
- Create expense charts.
- Add date-based filtering.
- Perform functional and usability testing.
- Fix identified defects.

**Expected Increment:** Users can review monthly expenses and visualize their spending patterns.

## 8. Scrum Events

- **Sprint Planning:** The team selects prioritized backlog items and defines a Sprint Goal.
- **Daily Scrum:** Developers discuss progress, upcoming work, and impediments.
- **Sprint Review:** The team demonstrates the increment and gathers stakeholder feedback.
- **Sprint Retrospective:** The team identifies improvements for the next sprint.

## 9. Definition of Done

A backlog item is considered Done when:
- Its acceptance criteria are satisfied.
- The implementation is complete.
- Relevant tests pass.
- The code is reviewed and integrated.
- No critical defects remain.
- The feature is demonstrated and accepted according to the team's Definition of Done.

## 10. Sprint Review and Retrospective

### Sprint Review
At the end of each sprint, the team demonstrates the completed work, gathers feedback, and updates the Product Backlog when necessary.

### Sprint Retrospective
The team reflects on collaboration, development challenges, testing, and time management. Improvements may include more realistic estimates, earlier testing, and clearer task ownership.

## 11. Git and GitHub Collaboration

Git and GitHub support version control and collaborative development.

- **Repository:** Stores project documentation and source code.
- **Issues:** Track user stories, tasks, and defects.
- **Projects:** Visualize and manage workflow.
- **Branches:** Allow changes to be developed separately.
- **Pull Requests:** Support code review and controlled merging.
- **Commits:** Maintain a history of project changes.

## 12. Final Project Outcome

The planned outcome is a personal finance management application with transaction recording, categorization, a financial dashboard, and monthly reporting.

The project is organized into three planned sprints to demonstrate iterative development, continuous feedback, teamwork, and incremental delivery.

**Note:** Sprint increments and outcomes described above are planned deliverables. They should be marked as completed only after the corresponding features have actually been implemented and tested.

## 13. Conclusion

This case study demonstrates how Agile and Scrum can organize software development into manageable iterations. Product Backlog prioritization, Sprint Planning, regular communication, reviews, and retrospectives help the team deliver value incrementally and improve the development process continuously.
