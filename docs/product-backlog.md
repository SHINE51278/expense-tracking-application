# Product Backlog
## Expense Tracking Application — Case Study 16

## 1. Purpose

The Product Backlog contains the features, requirements, and improvements planned for the Expense Tracking Application. The Product Owner prioritizes these items according to user value, importance, and dependencies.

## 2. Product Backlog Items

| ID | User Story | Priority | Story Points | Acceptance Criteria |
|---|---|---|---:|---|
| PB1 | As a user, I want to register and log in securely so that my financial data is protected. | High | 5 | Valid users can log in; invalid credentials are rejected. |
| PB2 | As a user, I want to record income so that I can track my earnings. | High | 3 | Users can enter an amount, date, and description; valid records are saved. |
| PB3 | As a user, I want to record expenses so that I can monitor my spending. | High | 3 | Users can enter expense details; invalid or negative amounts are rejected. |
| PB4 | As a user, I want to categorize transactions so that I can understand my spending habits. | High | 3 | Users can assign categories such as food, travel, education, and shopping. |
| PB5 | As a user, I want to view my financial summary so that I can understand my balance. | High | 5 | The dashboard displays total income, total expenses, and remaining balance correctly. |
| PB6 | As a user, I want to edit and delete transactions so that I can correct mistakes. | Medium | 3 | Users can update or remove a transaction and see the updated totals. |
| PB7 | As a user, I want monthly reports so that I can analyze my expenses. | Medium | 5 | Users can view income and expenses for a selected month. |
| PB8 | As a user, I want visual charts so that I can understand spending patterns. | Low | 5 | A chart summarizes expenses by category. |

## 3. Prioritization Strategy

The backlog uses three priority levels:

- **High:** Essential functionality required for the core application.
- **Medium:** Features that improve usability and financial analysis.
- **Low:** Additional features that can be delivered after the core requirements.

## 4. Sprint Allocation

| Sprint | Planned Backlog Items | Sprint Goal |
|---|---|---|
| Sprint 1 | PB1, PB2, PB3 | Enable user access and transaction recording. |
| Sprint 2 | PB4, PB5, PB6 | Organize transactions and provide a financial dashboard. |
| Sprint 3 | PB7, PB8 | Deliver monthly reports and visual analysis. |

## 5. Definition of Ready

A backlog item is Ready when:

- The user story is understandable.
- Acceptance criteria are defined.
- Priority has been assigned.
- The team understands the expected work.
- Dependencies and major uncertainties are identified.

## 6. Backlog Refinement

The Product Owner and development team review the backlog regularly. Items may be clarified, reprioritized, split into smaller tasks, or estimated as the team learns more about the application.

**Note:** Story points are initial estimates for this simulation. The team may revise them during backlog refinement.
